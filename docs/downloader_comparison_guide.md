# Сравнение подходов к скачиванию файлов в Python

В рамках проекта `python-file-loaders` для загрузки файлов (например, архивов городской статистики Divvy) реализовано четыре независимых метода. Каждый подход имеет свои архитектурные особенности, сильные стороны, ограничения и оптимальные сценарии применения.

---

## 1. Сводная сравнительная таблица

| Метод | Модель выполнения | Основной инструмент / библиотека | Скорость работы | Потребление ресурсов | Сложность реализации | Когда применять |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **`requests`** | Синхронная (блокирующая) | `requests` | Низкая (последовательно) | Минимальное | Низкая | Для небольших файлов, простых скриптов и отладки. |
| **`wget`** | Синхронная (системная обертка) | `wget` (внешняя утилита / обертка) | Умеренная | Низкое | Минимальная | Когда нужно скачать готовый файл одной строкой с докачкой. |
| **`thread`** | Многопоточная | `requests` + `ThreadPoolExecutor` | Высокая (параллельно) | Среднее (потоки ОС) | Средняя | Для параллельной загрузки независимых файлов с блокирующим I/O. |
| **`async`** | Асинхронная (неблокирующая) | `aiohttp` + `asyncio` | Максимальная | Низкое (один поток, Event Loop) | Выше среднего | Для массовой высокопроизводительной загрузки большого числа файлов. |

## 2. Подробный разбор каждого метода

### А. `requests` (Синхронный метод)
* **Как работает:** Выполняет HTTP-запросы последовательно (один за другим). Программа ждет завершения загрузки первого файла, прежде чем перейти к следующему.
* **Плюсы:** 
  * Простой, линейный и интуитивно понятный код.
  * Легко отлаживать, нет сложностей с многопоточностью или асинхронным контекстом.
* **Минусы:** 
  * Низкая пропускная способность при работе с множеством файлов, так как процессор простаивает в ожидании сетевого ответа (Network I/O Wait).
* **В каких случаях использовать:**
  * Загрузка **1–2 небольших файлов**.
  * Простые скрипты автоматизации, где скорость выполнения не критична.
  * Написание базовых юнит-тестов и прототипов.

### Б. `wget` (Метод обертки утилиты)
* **Как работает:** Использует стандартную логику утилиты `wget` через обертку или системный вызов.
* **Плюсы:**
  * Отличная встроенная обработка редиректов, таймаутов и возобновления прерванной загрузки (`resume`).
  * Минимальный объем кода со стороны разработчика.
* **Минусы:**
  * Зависит от окружения ОС или контейнера (требует наличия бинарника `wget` в системе).
  * Менее гибок для программной кастомизации из Python по сравнению с `requests`.
* **В каких случаях использовать:**
  * Быстрые разовые задачи в терминале или Docker-контейнерах, где утилита доступна из коробки.

### В. `thread` (Многопоточный метод)
* **Как работает:** Использует `ThreadPoolExecutor` из стандартной библиотеки. Создает пул потоков операционной системы, где каждый поток независимо и параллельно качает свой файл через `requests`.
* **Плюсы:**
  * Значительно ускоряет процесс за счет параллельного перекрытия сетевых задержек (время ожидания сети распределяется на несколько потоков).
  * GIL (Global Interpreter Lock) в Python корректно сбрасывается во время блокирующих операций ввода-вывода (I/O).
* **Минусы:**
  * Потоки ОС потребляют больше системной памяти по сравнению с корутинами.
  * Не подходит для экстремального параллелизма (например, тысяч одновременных загрузок) из-за ограничений ОС на количество потоков и дескрипторов файлов.
* **В каких случаях использовать:**
  * Классические **ETL-пайплайны среднего масштаба** (например, одновременное скачивание 5–20 архивов данных).

### Г. `async` (Асинхронный метод)
* **Как работает:** Построен на базе `asyncio` и библиотеки `aiohttp`. Выполняется в одном потоке внутри неблокирующего цикла событий (Event Loop), переключаясь между задачами в моменты сетевых пауз.
* **Плюсы:**
  * **Максимальная производительность и эффективность:** минимальные накладные расходы на память и процессор.
  * Позволяет эффективно обрабатывать тысячи одновременных сетевых соединений (High Concurrency).
* **Минусы:**
  * Более сложная архитектура (требует понимания синтаксиса `async/await`, управления семафорами и ограничения скорости).
  * Сложнее в отладке и профилировании.
* **В каких случаях использовать:**
  * Загрузка **массивных наборов данных**, состоящих из сотен или тысяч мелких и средних файлов.
  * Высоконагруженные системы, где критически важно утилизировать канал связи с минимальными затратами ресурсов ОС.
