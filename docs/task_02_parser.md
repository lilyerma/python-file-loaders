# Задача 2: Модульные экстракторы архивов

### 1. Постановка задачи
После успешной загрузки архивов с данными (например, `ZIP` или `GZ`) потребовалось автоматизировать процесс их распаковки и очистки дискового пространства. В рамках архитектуры нужно было вынести работу с архивами в независимые модули, поддержав как классическую распаковку на диск, так и потоковую обработку в оперативной памяти (**in-memory**) для избежания лишних операций ввода-вывода (I/O) на жесткий диск.

### 2. Что было сделано

#### А. Базовый интерфейс и менеджер ZIP (`ZipExtractor`)
В модуле `extractor.py` реализован класс для работы с архивами:
* Поиск и пакетная обработка `.zip` архивов в указанной директории.
* Безопасная распаковка содержимого в целевую папку.
* Автоматическое удаление оригинального архива после успешной распаковки для экономии дискового пространства.

#### Б. Gzip-экстрактор и работа в памяти (`GzipExtractor`)
Для работы с сжатыми файлами (`.gz`), которые часто встречаются в больших датасетах (например, в Common Crawl), был создан `extractors/gz_extractor.py`:
* Поддержка стандартной распаковки из файла на диск.
* **Распаковка в памяти (`decompress_to_memory`):** Возможность принимать байтовый поток (`io.BytesIO`), распаковывать его «на лету» в оперативной памяти с помощью встроенного модуля `gzip` и возвращать распакованный буфер без единой записи на жесткий диск (что критично для работы с CloudFront/S3 стримингом).
