# Задача 3: Потоковое чтение, профилирование памяти и S3-стриминг (Exercise 3)

### 1. Откуда взята задача
За основу взято **Exercise 3** из репозитория [Data Engineering Practice](https://github.com/danielbeach/data-engineering-practice), которое тестирует навыки многошаговой работы с облачными источниками данных (в оригинале — AWS S3 через `boto3`)[cite: 1].

### 2. Что было сделано и зачем
* **Отказ от Boto3 в пользу HTTP-стриминга:** Поскольку реализовать полноценное беспарольное подключение к целевому S3-бакету в рамках упражнения не удалось, пайплайн был адаптирован. Мы перешли на стандартные `requests` для скачивания индексных и целевых файлов по прямым публичным URL (в стиле CloudFront / Common Crawl).
* **Интеграция GzipExtractor (распаковка «на лету»):** Добавлена работа с `.gz` архивами прямо в оперативной памяти (`BytesIO`), что позволило избежать записи тяжелых промежуточных файлов на диск.
* **Универсальная читалка (`LineReader`):** Реализовано безопасное построковое чтение текстовых стримов (`TextIOWrapper`) без риска переполнения оперативной памяти (Out-Of-Memory).
* **Профайлер памяти (`memory_profiler`):** Внедрен контекстный менеджер на базе `tracemalloc` для контроля времени выполнения и пикового потребления RAM на каждом шаге.
