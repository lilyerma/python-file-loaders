# Архитектура пайплайна данных и миграций (Data & Migration Pipeline)

В данном разделе описана итоговая архитектура нашего ETL-пайплайна, инструментов аналитики и работы с базой данных PostgreSQL. Мы осознанно отошли от слепой автоматизации в пользу подхода *Human-in-the-Loop*, где автоматизация помогает принимать решения, а финальный контроль за структурой данных остается за разработчиком.

---

## 1. Концепция и эволюция пайплайна

1. **Отказ от автоматического сохранятеля (`SqlScriptSaver`):**
* В ходе проектирования мы отказались от идеи автоматически записывать сгенерированные DDL-скрипты через специальный класс-сохранятель. Это оказалось избыточным и неудобным для ручной корректировки связей.
* **Новый рабочий процесс:** Пользователь запускает анализ через CLI, видит статистику и предложенный каркас DDL в консоли, при необходимости дорабатывает его руками и фиксирует в репозитории как `.sql` файл миграции.


2. **Единая точка входа через CLI (`cli.py`):**
* Все операции инкапсулированы в удобный интерфейс командной строки. CLI выступает «корнем композиции» (Composition Root), связывая аналитические модули, менеджер баз данных и исполнители скриптов.

## 2. Структура и компоненты системы

```text
python-file-loaders/
 ├── csv_to_pg_loader/
 │    ├── data/                  # Источники (CSV-файлы)
 │    ├── sql/                   # Ручные SQL-миграции (.sql файлы)
 │    ├── analyzer.py            # Анализ типов, null и min/max
 │    ├── ddl_generator.py       # Генерация CREATE TABLE, PK и шаблонов FK
 │    ├── db_manager.py          # Управление подключением через SQLAlchemy
 │    └── sql_runner.py          # Пакетный исполнитель миграций в цикле
 ├── tests/
 │    └── test_connection.py     # Тест доступности PostgreSQL
 ├── cli.py                      # Интерфейс командной строки
 └── docker-compose.yml          # Инфраструктура (PostgreSQL в контейнере)

```

### Детализация модулей:

* **`CsvAnalyzer` (`analyzer.py`):**
Рекурсивно сканирует директорию с данными, вычисляет типы по Pandas, количество пустых значений (`null`), диапазоны (`min/max`) и длину строк для текстовых полей. Выводит подробный аналитический отчет.
* **`PostgresDdlGenerator` (`ddl_generator.py`):**
На основе структуры данных формирует корректный SQL-запрос `CREATE TABLE`. Автоматически определяет типы PostgreSQL, сохраняет исходный порядок колонок, добавляет поименованный `PRIMARY KEY` и готовый закомментированный шаблон `FOREIGN KEY` в конце таблицы.
* **Инфраструктура (`docker-compose.yml`):**
Поднимает изолированный контейнер с PostgreSQL (`postgres:15-alpine`) для локальной разработки, тестирования и применения миграций.
* **Менеджер подключений (`DatabaseManager`):**
Инкапсулирует работу с SQLAlchemy и драйвером `psycopg2`. Предоставляет безопасный контекстный менеджер (`get_connection()`) с автоматическим управлением транзакциями (commit/rollback).
* **Исполнитель миграций (`SqlScriptRunner`):**
Отвечает за пакетное выполнение. В цикле обходит указанную папку с готовыми `.sql` файлами, сортирует их и последовательно применяет в базе данных.

## 3. Основные сценарии использования (CLI)

### А. Анализ данных и получение DDL-шаблона

```bash
python cli.py analyze --input csv_to_pg_loader/data

```

*Результат:* Вывод в консоль подробного профиля данных (типы, пропуски) и готового SQL-скрипта `CREATE TABLE`, который можно скопировать, отредактировать и сохранить в папку `sql/`.

### Б. Проверка подключения к базе данных

```bash
python tests/test_connection.py

```

*(При необходимости запуска с учетом путей пакета: `PYTHONPATH=. python tests/test_connection.py`)*
*Результат:* Проверка доступности Docker-контейнера с PostgreSQL и вывод версии СУБД.

### В. Пакетный запуск SQL-миграций

```bash
python cli.py sql-run

```

*Результат:* Сканирование папки `csv_to_pg_loader/sql`, последовательное выполнение всех `.sql` файлов в базе данных с логированием успешных шагов и обработкой ошибок.
