# 📊 Задача 7: Распределенный PySpark-пайплайн анализа жестких дисков и In-Memory обработка архивов

В данном модуле реализован распределенный пайплайн обработки больших объемов данных (на примере статистики отказов жестких дисков Backblaze) с использованием **Apache Spark**, архитектурных шаблонов оптимизации вычислений и чтения архивов «на лету» без записи на жесткий диск.

---

## 🏗 Архитектурные решения и ключевые особенности

### 1. In-Memory чтение ZIP-архивов (`sc.binaryFiles`)
Для соответствия требованиям эффективного использования ресурсов и избежания избыточного I/O на дисковую подсистему, стандартный механизм распаковки был заменен на распределенное чтение в оперативную память:
* Архивы с двойными расширениями (например, `.csv.zip`) считываются на уровне драйвера и воркеров как бинарные потоки с помощью `sc.binaryFiles()`.
* С помощью Python-модулей `io.BytesIO` и `zipfile` архив распаковывается *ин-момори* (внутри памяти воркера), а строки целевого CSV-файла потоково передаются (`yield`) через `TextIOWrapper` в RDD без создания промежуточных файлов на диске.

### 2. Оптимизация структуры пайплайна и колоночной проекции
* **Ранняя проекция (.select):** Сразу после ингестации датасета отсекаются избыточные метрики (сотни SMART-показателей оригинального датасета), оставляя только необходимые для аналитики поля (`source_file`, `extracted_date`, `model`, `capacity_bytes`). Это радикально снижает нагрузку на сеть (`shuffle`) и оперативную память.
* **Выделение метаданных:** Автоматическое извлечение даты из имени архива/файла с помощью регулярных выражений (`regexp_extract`) и простановка имени файла через `lit()`.

### 3. Квантилирование емкости через вторичные справочные датафреймы
Для генерации рангов и квантилей дисков по их объему (`capacity_bytes`) применяется двухшаговая архитектура:
1. **Создание легковесного справочника:** Из основного датасета выделяются только уникальные пары `model` и `capacity_bytes` (`.distinct()`).
2. **Оконные функции и `ntile(5)`:** Уникальные модели сортируются от наибольшего объема к наименьшему (`Window.orderBy(desc("capacity_bytes"))`), после чего распределяются ровно на 5 квантилей с помощью функции `ntile(5)` (где ранг `1` соответствует самым емким накопителям). Для чистоты плана выполнения используется `.repartition(1)` над справочником.
3. **Обратный обогащающий джоин (`left join`):** Полученный идентификатор квантиля (`storage_quantile_id`) подтягивается обратно в основной лог по ключу модели.
4. **Выделение брендов:** С помощью комбинации функций `split` и `element_at` из строки модели (`model`) извлекается бренд накопителя (первое слово).

### 4. Динамическая маршрутизация запросов и CLI
Оркестратор пайплайна поддерживает гибкий запуск:
* Пакетный прогон всех аналитических модулей (`q1` — `q6`).
* Выполнение строго определенного целевого запроса (например, `--query q7`) с использованием динамического импорта модулей (`importlib`) и трекинга выполнения.
