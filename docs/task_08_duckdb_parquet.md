# Задача 8: Аналитика, трансформации и Parquet-партиционирование на DuckDB

## 🎯 Цели и задачи
В рамках данного упражнения (на базе **Exercise 8** из `danielbeach/data-engineering-practice`) перед инженером ставится задача эффективной аналитической обработки данных с использованием встроенного движка **DuckDB**. 

Основные требования:
1. Выполнение произвольных аналитических SQL-запросов.
2. Нативная выгрузка результатов запросов в колоночный формат **Apache Parquet**.
3. Поддержка **динамического партиционирования** данных на уровне движка (`PARTITION_BY`).

---

## 🏛 Архитектурные решения

### 1. Выделенный сервис экспорта (`ParquetExporter`)
Чтобы не перегружать базовые менеджеры соединений и оркестраторы папок, логика точечного экспорта вынесена в специализированный класс `ParquetExporter` (расположенный в `db_managers/parquet_exporter.py`).

### 2. Интеграция в CLI через паттерн плагинов
Новая команда parquet-run оформлена в виде изолированного модуля в папке commands/parquet_run.py. Главный диспетчер new_cli.py автоматически подхватывает её при старте с помощью функции register_command(subparsers).

Аргументы командной строки:

--db-type (-t): Тип базы данных (по умолчанию duckdb).

--file (-f): Путь к .sql файлу с аналитическим запросом.

--output (-o): Путь к директории для сохранения результирующих Parquet-файлов.

--partition-by (-p): Список полей для партиционирования (передаются через пробел).
