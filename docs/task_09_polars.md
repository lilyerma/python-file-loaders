# Решение Exercise 9: Ленивые вычисления с Polars (Polars Lazy API)

Решение практического задания **Exercise 9** из репозитория `danielbeach/data-engineering-practice`.

Основная цель задания — научиться работать с библиотекой **Polars**, используя **LazyFrame API** (`scan_csv`, ленивые цепочки трансформаций и вызов `.collect()`) для эффективной обработки данных без полной загрузки всего датасета в оперативную память.


## 📋 Основные шаги реализации

1. **Определение схемы данных**: Явное задание типе данных (`schema`) для избежания ошибок парсинга и экономии памяти (`pl.Categorical` для категорий, `pl.Utf8` для ID станций).
2. **Ленивое чтение (`pl.scan_csv`)**: Создание графа вычислений без мгновенной загрузки файла в память.
3. **Агрегация по дням**: Выделение даты из `started_at`, подсчет поездок (`ride_count`) и сортировка.
4. **Сравнение недели к неделе (Week-over-Week)**:
* Вычисление номера недели (`week`) и дня недели (`weekday`).
* Соединение таблицы самой с собой (`LEFT JOIN`) со сдвигом недели на `+1` для сравнения с прошлым аналогичным днем.
* Безопасное вычисление разницы (`diff`) с приведением типов к знаковым целым (`pl.Int64`) во избежание `underflow`.


5. **Вычисление агрегированной статистики**: Расчет `min`, `max` и `mean` поездок по неделям.
6. **Материализация (`.collect()`)**: Выполнение оптимизированного графа вычислений.

---


## 🚨 Особенности и частые ошибки (Lessons Learned)

1. **Избегание Unsigned Underflow (`u32`)**:

    По умолчанию агрегаты `.count()` и `.len()` в Polars имеют беззнаковый тип `u32`. Вычитание меньшего из большего (`16 - 43`) приводит к переполнению типы в `4294967269`. Решение — явное приведение `.cast(pl.Int64)` перед математическим вычитанием.
2. **Согласование типов ключей JOIN (`SchemaError`)**:

    Для `join(on=["weekday", "week"])` типы колонок в обоих `LazyFrame` должны совпадать с точностью до бита. Каст ключей к `pl.Int32` предотвращает падение с ошибкой несоответствия типов `String` / `Datetime` / `Int`.
3. **Своевременный вызов `.collect()**`:
    Без `.collect()` обращение к переменной или вызов `print()` выведет только неоптимизированный план вычислений (`naive plan`), а не итоговые данные.
